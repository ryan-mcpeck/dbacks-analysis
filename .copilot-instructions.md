# Copilot Instructions for DbacksAnalytics Pro

## 📋 Project Overview

### Core Application
- **Primary Tool**: `dbacks_analytics_pro.py` - Professional consolidated dashboard
- **Data Source**: MLB Statcast data via pybaseball library
- **Season Coverage**: Complete 2025 season (March 20 - September 28)  
- **Dataset**: `dbacks_team_statcast.csv` - 24,946+ pitches analyzed

### Project Structure
- **Main Dashboard**: Single professional interface with tabbed navigation
- **Data Updates**: Smart incremental refresh with `update_dbacks_statcast.py`
- **Legacy Archive**: Previous dashboard versions stored in `legacy/` folder
- **Documentation**: Comprehensive README with usage guides and feature explanations

## 🧹 Development & Cleanup Standards

### File Management
- **Always clean up temporary files** after debugging sessions (test_*.py, debug_*.py, *_simple.py)
- **Archive old versions** instead of deleting - move to `legacy/` folder
- **Use descriptive file names** that indicate purpose and status
- **Remove backup/duplicate files** once main version is confirmed working

### Process Management
- **Always stop Streamlit processes** when switching between dashboard versions
- **Use taskkill /F /IM streamlit.exe** to ensure clean process termination
- **Test on different ports** (8501, 8502, etc.) to avoid conflicts during development

### Code Development Workflow
1. **Create test versions** for debugging (e.g., `test_basic.py`)
2. **Identify and fix issues** in isolated test environment
3. **Apply fixes to main application** (`dbacks_analytics_pro.py`)
4. **Test main application thoroughly**
5. **Clean up all temporary files** once main version works
6. **Update documentation** if significant changes made

### Error Handling Protocol
- **Always include comprehensive error handling** in data processing functions
- **Add progress indicators** for long-running operations (st.spinner, st.success)
- **Validate column existence** before performing operations
- **Provide fallback values** for missing or corrupted data
- **Log debug information** during development, remove for production

## ⚾ Baseball Analytics Guidelines

### Data Understanding
- **Statcast data**: High-resolution pitch-by-pitch data from MLB
- **Key fields**: pitch_name, release_speed, player_name, game_date, pitch_type
- **Team identification**: home_team='AZ' or away_team='AZ' with inning_topbot logic
- **Pitcher roles**: First inning = starters, later innings = relievers (with exceptions)

### Analysis Standards
- **Minimum thresholds**: Require sufficient sample sizes (e.g., 10+ starts for starters)
- **Context matters**: Consider game situations, pitch counts, leverage index
- **Seasonal trends**: Account for player development and injury effects
- **League comparisons**: Compare D-backs stats to league averages when relevant
